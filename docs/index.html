Llama / Tulu replication

The 52 prompts, source-character anchors, matched controls and 39 sampled sites are reused from Qwen. Both Llama subjects use the same Tulu template. Each activation is captured from a separately tokenized prefix ending at the exact source-character boundary; this avoids merging final punctuation with a template newline. Actual replies use the full chat template. L56 (56 of 80 blocks) is the nearest trained relative depth to Qwen’s block-45 input (45 of 64 blocks).

Each trained lens uses its native prompt and normalized input-embedding injection. Subject activations are BF16; the oracle uses its trained FP8 backbone and GRPO adapter. Readouts request 10 phrases of 8 tokens, greedy or sampled at temperature 0.7 / top-p 0.9, with a 256-token cap. All output lines remain in generated order, without best-of selection or phrase sorting.

Validation v2 separates causal masking from numerical sensitivity: identical-input repeats and future-content substitutions at fixed sequence length must match exactly. Changes caused by sequence length are measured separately, including extra diagnostic decodes excluded from the primary analysis. The original failed run is preserved.

The User/Assistant rubric is the same as Qwen. Missing labels are pending, never imported from another model. No corresponding J++ lens is substituted.

The base model is evaluated using the Tulu chat format; this is not a raw-text base-model experiment. See the frozen replication protocol.

What this pilot tests

Do readouts follow the user's expressed stance, the Assistant's assessment, or both? An assessment that conflicts with the user's belief and follows the factual controls counts as evidence for an Assistant-side perspective. Explicit first-person wording is not required.

Eight families test conflicting appraisals or goals. Bereavement and frustration are auxiliary relational-role tests. Each factual pair keeps the user's stance fixed. Arithmetic, tutoring, and frustration also cross the stated appraisal. Every message is tested as a direct request and under an exact-copy instruction.

Readout positions

Fact boundary; primary appraisal boundary; final token of the user's request. Confidentiality has no separate appraisal boundary. Bereavement uses the end of the letters sentence. Tylenol additionally includes the pre-dose prefix, the historical “is” anchor, and the completed relief statement. The highlighted token marks exactly how much text the activation has seen. Later text is muted.

Measurements and controls

J++ is read at block outputs 8, 16, 24, 32, 40, 44, 48, and 56. Full user-token trajectories are secondary. Raw and alphanumeric-filtered rankings are retained. Fixed concept groups use audited single-token IDs; scores and ranks are exploratory diagnostics, not probabilities of a thought.

The O-lens receives the raw residual entering block 45 through the released overwrite hook and native prompt builder, requesting ten phrases of eight tokens. It sees no source text or perspective labels. Malformed and truncated outputs remain visible. Paired and unrelated activation controls reference their corresponding decodes because the oracle prompt is identical for all sites. A no-injection baseline measures the decoder prior. Five seeded samples at temperature 0.7 and top-p 0.9 are taken at a fixed quarter of sites.

The public O-lens checkpoint does not specify its training placeholder. This pilot fixes <|box_start|>, as in the existing local replication, before study readouts and requires independent topic-recovery calibration. This is an implementation limitation; calibration does not prove full fidelity.

Checks include exact anchor-token mapping, equality of block 44 output and block 45 input, final-head parity, and shared-prefix invariance across every factual pair. Failure stops the worker. Generated replies are external behavioral checks, not ground truth about internal state. No automated perspective classification is presented as a validated result.
