Privilegedness of the assistant (Oracle Lens): replication with two newer O-lenses

In the post, we used the O-lens to ask whether Qwen3.6-27B represents the user's perspective or the assistant's while it reads a user message. Here we reran the same experiment with two newer O-lenses for the same model, to check whether the result depends on the particular lens.

The two new lenses both read the output of block 56, a later layer than the original lens (block 45):

OriginalThe O-lens used in the post (ceselder), reading the input to block 45, greedy decoding. rl600Agam's O-lens (olens_s3d_rl600). It was trained only on positions inside the assistant's reply, so it has never been trained to read a user token. s225Our continuation of rl600, trained further on user-turn, chat-template and thinking positions.

Since s225 and rl600 differ only in whether the lens was trained on user tokens, comparing them also tells us whether a lens's training data changes how much "assistant" it reads into a user message.

Setup

We used exactly the same 26 messages, the same system prompt ("You are an AI assistant.") and the same three positions as the original:

  1. Fact boundary: after the relevant factual information, such as the user's arithmetic answer.
  2. Primary/appraisal boundary: after the sentence describing what the user thought or felt about the situation (e.g., their confidence in an answer or frustration with the assistant).
  3. Request boundary: at the end of the complete user message, after the user had asked the assistant to do something.

As before, we tested each message under two instructions: one asking Qwen to respond normally (Assist), and one asking it to copy the user's message without answering (Copy). We checked token by token that every position matched the original experiment.

We then used GPT-5.4, with the post's classification prompt unchanged, to label each phrase by whose perspective it expressed:

  • User: the user's feelings, beliefs, goals, or perspective, either explicitly attributed to the user or implied by the context.
  • Assistant: the assistant's judgments, reactions, intended responses, or response plans.

As before, a phrase could receive both labels, or neither.

What we had to change

The newer lenses don't produce output in the same shape as the original, so three things differ:

  1. Phrase length. The original lens writes about 20 separate 8-token phrases per readout. The newer lenses write about 4 bullet points of ~24 tokens each. A long bullet almost always contains something about the user, so labelling whole bullets pushes the User share to 92–96% and makes it incomparable with the original. To compare like with like, we cut each bullet into 8-token pieces and labelled those.1
  2. Sampling. The original used greedy decoding. The newer lenses were trained with sampling, so we sampled (temperature 0.8). The figures use one sampled readout per position. We drew 8 more per position to check that the results aren't a fluke of one sample.2
  3. Layer. Block 56 sits later in the model (closer to its output) than block 45. Some differences between the original and the new lenses may come from the layer rather than the lens.

We also checked that each new lens was the one we meant to load: at a position where the two lenses are known to differ sharply, both behaved as expected.3

  • The main result replicates. As in the original, the user's perspective appeared more often than the assistant's on user tokens. With rl600, the share of phrases with user content is almost identical to the original ( vs ). With s225 it is higher ().
  • Copy again reduces the assistant's perspective, by more than before. Moving from Assist to Copy, the share of phrases with assistant content falls from to for the original lens, from to for rl600, and from to for s225. So with the newer lenses, the assistant's perspective looks even less privileged when Qwen is only asked to copy.
  • The lens's training matters. s225 reads less of the assistant than rl600 does: points of assistant content under Assist, and under Copy.4 The gap is largest at the fact boundary (assistant-only phrases: → ) and the request boundary ( → ). rl600 was only ever trained on assistant replies, and it tends to describe a user token as if the assistant were already answering ("Let's verify your calculation step by step…"). s225, trained on user tokens, more often reads out the user's own words.
  • At the end of the request, the newer lenses see more of the assistant. Under Assist, rl600 labels of phrases at the request boundary as assistant-only, against for the original lens. A plausible explanation is the later layer: by the end of the user's request, block 56 may already be planning the reply. This is also why the newer lenses show a larger Assist–Copy difference at the request boundary.

For all readouts and their classifications, use the Lens switch in the O-lens section of the dashboard. It shows the original, rl600 and s225 readouts at each position. For the new lenses, each bullet is shaded by the labels of its 8-token pieces, and the 8 extra sampled readouts are listed below it.

As with the original, there's a lot of room for interpretation here. The new lenses differ from the original in layer, output format and decoding, and GPT-5.4 is an imperfect judge. Still, the basic picture holds across three different lenses: the user's perspective is often represented on user tokens, and the assistant's perspective is not overwhelmingly privileged. The comparison between rl600 and s225 suggests that how much assistant content a lens reports depends partly on what the lens was trained on, which is worth keeping in mind when interpreting O-lens readouts in general.
