O-lens · whose perspective on user tokens?

Dashboard (all readouts)

Privilegedness of the assistant (Oracle Lens)

To investigate how privileged the assistant persona is on user turns, we constructed a set of scenarios in which the user's perspective differed markedly from the assistant's.

For example, a user might confidently insist that 17 × 6 = 112, even though the correct answer is 102.

  • If the model was representing the user's perspective, we might expect to see representations of confidence in the answer.
  • If it was representing the assistant's, we might instead see a recognition of the user's mistake and an intention to correct it.

We tested 26 such messages on Qwen3.6-27B. Using the O-lens (block 56 output, the olens-qwen3.6-27b-userthink-s225 checkpoint), we examined the model's activations at three points while it processed each user message:

  1. Fact boundary: after the relevant factual information, such as the user's arithmetic answer.
  2. Primary/appraisal boundary: after the sentence describing what the user thought or felt about the situation (e.g., their confidence in an answer or frustration with the assistant).
  3. Request boundary: at the end of the complete user message, after the user had asked the assistant to do something.

We tested each message under two instructions:

  • Assist: Qwen is asked to respond normally.
  • Copy: Qwen is asked to copy the user's message without answering.

If assistant-like reactions appeared even when Qwen was only asked to copy the user's message, this would suggest that the model represents the assistant's perspective by default, even when the task doesn't call for it.

This O-lens describes an activation in a few bullet points of about 24 tokens each. A long bullet almost always contains something about the user, so we split each bullet into 8-token phrases and classified those.1 The lens was trained with sampling, so we sampled its readouts (temperature 0.8). The figures use one readout per position; we drew eight more to check the results.2

Next, we used GPT-5.4 to classify 1,894 phrases across 152 O-lens readouts according to whose perspective they expressed:3

  • User: the user's feelings, beliefs, goals, or perspective, either explicitly attributed to the user or implied by the context.
  • Assistant: the assistant's judgments, reactions, intended responses, or response plans. This included:
    • phrases explicitly attributed to the assistant;
    • unattributed evaluations that could reflect the assistant's judgment;
    • instructions or plans for how the assistant should respond.

Note: O-lens readouts are noisy and often contain phrases that could plausibly reflect either perspective. A phrase could therefore receive both labels, or neither, and we distinguish these categories below.

There's a lot of room for interpretation here, and we'd caution against drawing strong conclusions without more robust readouts and controls. Still, it seems clear that the user's perspective is often represented, and that the assistant's perspective largely recedes when Qwen is asked to copy instead of respond.

Notes

  1. Classifying whole bullets gives the same direction (Assistant content falls under Copy), but user content then appears in 96% of bullets, which hides most of the variation. Phrases from the same bullet are not independent, so all intervals resample whole messages.
  2. Using all nine readouts per position (1,404 readouts, classified per bullet by GPT-5.4-mini), the drop in assistant content from Assist to Copy is −28.6 points [−34.9, −22.0]. Using only the first readout, as in the figures, it is −28.8 points. So the results are not a fluke of one sample.
  3. GPT-5.4 was an imperfect judge, and the classification criteria are fairly subjective. A second judge (GPT-5.4-mini) agreed with GPT-5.4 on 86% (User) and 91% (Assistant) of phrases. We expect the numbers to be roughly in the right range, but you should assign substantial uncertainty around them. Confidentiality messages have no separate appraisal sentence, so their fact-boundary readout also stands in for the primary/appraisal panel. That is why there are 152 readouts rather than 156.
  4. Brackets are 95% bootstrap intervals over the 26 messages, with each message's Assist and Copy versions resampled together.
